# 12. MCP / Tool Connections

MCP (Model Context Protocol) connections are optional development integrations. Asrar-e-Tibb must build and deploy without an MCP server being present. Do not add MCP as a runtime dependency of the public app unless a concrete user-facing feature requires it and a security review approves it.

## Recommended developer-only tools
- GitHub integration for repo/PR/issue workflow, using minimum repository permissions.
- Supabase MCP only for development/staging inspection when available; restrict project and operations. Use read-only access for initial audit. Do not allow an AI agent to run arbitrary production SQL without explicit owner approval and backup.
- Figma integration if the owner later wants design assets to be pulled from Figma; do not block UI implementation on it.
- Render/Vercel dashboards for deployment status, with owner-controlled logins; never place dashboard credentials in `.env` or source.

## Safety rules
- Connectors are developer tooling, not a reason to bypass RLS or require privileged browser access.
- Use separate staging credentials and least privilege. No production service-role key in a coding prompt or MCP config committed to Git.
- Do not return health/personal records as AI context. Use synthetic fixtures for tests.
- Review SQL and deployment diffs before applying them. Disable/unlink tool access if it is no longer needed.
- `.mcp.json` or other tool config must not contain literal tokens/passwords. If a local config references environment variables, document variable names only and add secrets to ignore rules.

## When to skip MCP
If no connector is configured, work with checked-out source code, schema exports and official CLI commands. Never invent successful connector access or imply that the Supabase project was inspected if it was not.
