# 9. Setup Guide — Windows Laptop

## A. Get the project files onto your laptop
You do not need an existing local copy. The repository is public at <https://github.com/altafur-fuad/Asrar-E-Tibb>.

### Option 1 — Git clone (recommended)
1. Install Git for Windows from <https://git-scm.com/download/win> if needed.
2. Open **PowerShell** or the VS Code terminal.
3. Run:
   ```powershell
   cd $HOME\Documents
   git clone https://github.com/altafur-fuad/Asrar-E-Tibb.git
   cd Asrar-E-Tibb
   code .
   ```
   If `code .` is unavailable, open VS Code → **File → Open Folder** → select `Documents\Asrar-E-Tibb`.
4. Update an existing clone later with `git pull --ff-only` after checking `git status`.

### Option 2 — Download ZIP
1. Open the repo link in a browser.
2. Click **Code → Download ZIP**.
3. Extract the ZIP into a stable folder such as `Documents\Asrar-E-Tibb` (do not open/run it while still inside the ZIP viewer).
4. Open the extracted folder in VS Code. This method is fine for viewing/building, but Git clone is better for future changes and pushing commits.

### Important Git safety
Before an AI agent edits anything run `git status --short`. Commit a known-good baseline or make a backup copy. Never paste `.env` contents, access tokens, database passwords, or Android signing files into a prompt. Check `.gitignore` before building/releasing.

## B. Flutter Android app
Install Flutter SDK and Android Studio/Android SDK using their official Windows setup guides; verify Android toolchain is configured. Then in repo root:
```powershell
flutter doctor
flutter pub get
flutter analyze
flutter test
flutter devices
flutter run
```
Do not skip errors from `flutter doctor`; resolve the Android toolchain items relevant to the selected device/emulator. If the project requires Supabase settings, use the documented local environment method; do not hard-code new secrets in source.

Build a release APK only after auditing package ID and signing configuration:
```powershell
flutter build apk --release
```
The typical artifact is `build\app\outputs\flutter-apk\app-release.apk`, but confirm the actual output in the build log. A release APK intended for public download must be appropriately signed and tested on a clean Android device. Protect the upload keystore and passwords; never commit them.

## C. Node.js website
Install an active LTS version of Node.js and npm from official sources. From repo root, after `website/` is created:
```powershell
cd website
npm install
npm run dev
npm run lint
npm run build
```
Use only scripts that actually exist in `website/package.json`; report if commands are missing. Set variables in a local ignored `.env.local` file based on `website/.env.example` (if generated). Do not copy service-role secrets to variables prefixed `NEXT_PUBLIC_`.

## D. Rust API / Docker
Install Rust stable using the official Rust installation instructions; optionally install Docker Desktop for local image testing. After `backend/` is implemented:
```powershell
cd backend
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo build --release
```
If Docker is installed:
```powershell
docker build -t asrar-e-tibb-api .
docker run --rm -p 10000:10000 --env-file .env asrar-e-tibb-api
```
Use a local `.env` file populated with locally-created test settings. It must remain untracked. These are target commands; do not expect them to work before the Rust project exists.

## F. Environment variables
The pack contains `.env.example` with names/placeholders only. Use Vercel Project Settings → Environment Variables for website settings; Render Environment settings for backend secrets; local ignored files for development. Keep separate development/staging/production values. Never commit `.env`, `.env.local`, production SQL dumps or user data.

## G. Troubleshooting baseline
- Git says host cannot be resolved: check internet/DNS, then retry clone or use GitHub Download ZIP.
- `flutter` command not found: install Flutter and add its `bin` folder to PATH; reopen terminal.
- Android device missing: check `flutter devices`, SDK/emulator and USB debugging when using a physical phone.
- `flutter pub get` fails: capture the exact error and SDK/dependency versions; don't bulk-upgrade packages blindly.
- Supabase sign-in redirects back to the wrong URL: inspect site URL, exact redirect allowlist and app link callback; do not use wildcard origins as a permanent shortcut.
