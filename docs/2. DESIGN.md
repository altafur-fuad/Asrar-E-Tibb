# 2. UI / UX Design System

## 2.1 Direction
Create a modern, premium and credible health/pharmacy experience. Use the supplied reference screenshots for layout and mood, not as pixel-by-pixel templates. Keep Asrar-e-Tibb's identity recognizable and consistent across the Flutter app and website. Avoid generic admin dashboards, excessive gradients, fake metrics, intrusive banners and overcrowded product grids.

## 2.2 Suggested tokens
Treat these as starting tokens and tune them against the current logo/assets after audit:
- Forest: `#064E3B` (primary brand/navigation/footer)
- Evergreen: `#0B6B4B` (primary actions)
- Fresh green: `#23845B` (success/selection)
- Warm ivory: `#F7F7F2` (page background)
- Pure white: `#FFFFFF` (surfaces)
- Deep ink: `#12231D` (main text)
- Muted text: `#64746C`
- Soft sage: `#E6F0EA` (subtle blocks)
- Amber: `#E6B84B` (limited promotion/accent only)
- Danger: `#B42318`; warning: `#8A5A00`

Use color tokens by semantic purpose, not arbitrary per-page colors. Verify text contrast. Add dark theme only if current app supports it cleanly; do not spend the first milestone building two incomplete themes.

## 2.3 Typography and spacing
- Use a highly readable UI font with good Bangla glyph support if Bangla localization is introduced; verify licensing and packaging before bundling.
- Establish a type scale: display hero, page title, section heading, card title, body, metadata and label. Avoid giant hero typography on small phones.
- Use an 8-point base spacing rhythm, consistent card radius, restrained shadows and clear section spacing.
- Standard components: search box, segmented filters, category tile, medicine card, status pill, author row, post card, comments panel, empty state, skeleton, form field, toast/banner, confirmation dialog and pagination/load-more.

## 2.4 Website homepage hierarchy
1. Compact service strip only if delivery/support statements are true and configurable.
2. Header: logo, Medicines, TibbNews, Pharmacy, Consultation, About; prominent search; account/cart; mobile nav drawer.
3. Hero: concise trust-oriented copy, medicine search field, primary “Explore medicines” and secondary “Download Android app”; use only licensed/owned imagery or a tasteful dataset-backed product composition.
4. Browse by category using real categories inferred from dataset; avoid hard-coded unsupported departments.
5. Curated medicines with image mapping, brand/generic, strength/form when present, transparent price/availability when backed by data.
6. TibbNews editorial previews from real posts; distinguish verified credentials from unverified community profiles.
7. How consultation works with clear pay-first disclosure and disabled CTA if no provider/payment backend is ready.
8. Service/trust features; no “100% safe,” “guaranteed,” fake rating or customer count claims.
9. App download and footer with contact/legal links.

## 2.5 Medicine card & detail page
- Card: real product image, brand/common name, generic name if available, strength/form, price only if trusted, stock/availability only if current, details button.
- Detail: clearly separate dataset facts from editorial explanation; synonyms/alternatives only if mapped from validated data; no dosage recommendation invented from the product name; include information disclaimer.
- Handle missing/broken image with a local placeholder, never a mismatched photo of another medicine.
- On the web, use pagination/search rather than rendering the complete medicine dataset on the homepage.

## 2.6 TibbNews
- Use editorial reading hierarchy and readable line length; author name, role/verification state, date and post actions.
- Keep long articles easy to read; avoid making doctor posts look like paid ads.
- Comment/reply actions have clear signed-out states, loading/error feedback and moderation/report access.
- Uploaded HTML is untrusted. Sanitize rich content or use a restricted Markdown renderer; never render arbitrary user HTML directly.

## 2.7 Flutter app modernization
- Audit every existing screen first. Keep routes/features and migrate one screen family at a time.
- Align app bar, drawer/bottom navigation, inputs, cards, dialogs and colors to the same tokens.
- Improve small phone layouts, large text scaling, loading/empty/offline/error states, tap target size and input validation.
- Test on Android emulator and real device if available. Do not break currently configured native platform files.

## 2.8 Motion and accessibility
- Keep transitions brief and subtle. Respect reduced-motion preferences on web where supported.
- Provide focus-visible styles, keyboard navigation, meaningful alt text, form labels, status announcements and touch targets.
- Never use color alone for role, payment or stock status.

## 2.9 Reference assets
See [`REFERENCE_ASSETS.md`](REFERENCE_ASSETS.md). The screenshots cover pharmacy storefronts, clinic sites, wellness and reminder interfaces. Keep the target visual identity Asrar-e-Tibb, not the brands/text appearing in those screenshots. Avoid importing competitor marks, fake clinicians, product labels or claims.
