# 13. Integration Plan

## 13.1 Supabase
- Retain Auth/Postgres/Storage/Realtime unless audit indicates a concrete blocker.
- Use publishable/anon key only in clients with policies correctly enforced. Never use a service-role/secret key in browser/mobile code.
- Set exact site/redirect URLs for localhost and Vercel preview/production. Keep staging and production separated.
- Audit Realtime publication access and Storage buckets, not just table SELECT.

## 13.2 Vercel website
- Root directory should point to `website/` in a monorepo.
- Use preview deployments for PRs and a protected production branch.
- Configure only browser-safe variables (e.g. Supabase project URL and publishable key, public API base URL, public APK release URL). No database credentials, payment secrets or service-role keys.
- Add route fallback/404, security headers, cache policy and error handling. Never publicly cache private account/order/reminder responses.

## 13.3 Render Rust API
- Build from `backend/Dockerfile`; production listens on `0.0.0.0:$PORT`.
- Use Render's environment settings for server secrets. Configure health check path, region, allowed website origins, logs and deploy notifications.
- Use a migration step that is explicit, reviewed and safe for rolling deploy; do not drop/recreate tables at server startup.
- If using Supabase Postgres directly, use supported TLS and connection settings; consider pooler/limits as appropriate. Never expose DB port/credentials to clients.

## 13.4 GitHub Releases / APK
- Build APK with the project's actual package/application ID and protected signing key.
- Attach APK to a versioned GitHub Release, with version name/code, release date, minimum Android/API notes if verified, SHA-256 checksum and known limitations.
- Website download CTA uses a configurable URL to the latest verified release. Do not hard-code a non-existent release URL and claim it's ready.
- Verify the exact URL and checksum after uploading; test download on phone/mobile data and a clean Android device.
- Warn that Android may ask the user to allow installs from their chosen browser/file manager. Explain this safely; do not encourage bypassing Play Protect or ignoring unknown/unverified files.

## 13.5 Payment and consultation provider
Provider is **not selected in this plan**. Before integration, confirm merchant availability, test/live credentials, webhook signature rules, refunds/cancellations, fees, currency, receipts, payment-failure behavior and legal requirements. Use an adapter interface so provider-specific code is isolated. No fake transactions or success buttons. Only validated server status unlocks a paid appointment/session.

## 13.6 Email, notifications and uploads
- Auth email/password reset depends on Supabase Auth settings and email provider; test delivery and redirects.
- Push/email notifications need consent, preferences, delivery retry, abuse controls and no sensitive content in subject/previews by default.
- Image uploads use allowed MIME types, size limits, ownership-bound storage policy, safe file naming and deletion/orphan cleanup.
- Prescription uploads remain disabled/Coming Soon until retention, access and clinical safety are approved.

## 13.7 Medicines source/import
Document source/license if known, dataset version, import date, field mapping, duplicate handling and image matching. Do not assume local dataset prices or stock are real commerce data.
