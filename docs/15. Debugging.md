# 15. Debugging & Incident Playbook

## General procedure
1. Reproduce the issue and capture exact steps, platform, version and sanitized error.
2. Compare against the recorded baseline; inspect `git diff` and `git status`.
3. Find the smallest relevant source path; do not rewrite a module to fix an unknown error.
4. Avoid logging tokens, passwords, personal notes, reminders, prescription content or full payment payloads.
5. Add a regression test, run affected tests/build, document cause and rollback.

## Common failure classes
### Flutter dependency/build errors
- Run `flutter doctor -v`, `flutter pub get` and capture first root-cause error.
- Check Flutter/Dart version compatibility and Android SDK/Gradle/JDK settings before changing dependency versions.
- Avoid blind `flutter pub upgrade --major-versions` and destructive cache-clearing as first response.

### Supabase sign-in/redirect failures
- Confirm project URL/public key is correct for environment, Auth site URL, exact redirect allowlist and app deep-link configuration.
- Check session listener lifecycle and token refresh; avoid manual token parsing for authorization.
- Confirm account verification and blocked status using safe test accounts.

### RLS “permission denied” or unexpected data
- Determine which DB role/JWT claim is used; check SQL grants and RLS policy separately.
- Test as a real client user, not the database owner. Verify USING and WITH CHECK logic, views, RPCs, realtime and Storage.
- Never “fix” the error by disabling RLS or granting everyone access. Write the intended policy and negative tests.

### Web site does not build/deploy
- Verify Vercel root directory is `website/`, build command/lockfile and Node version are appropriate.
- Inspect build logs and env variable names, not secret values. Check no `.env.local` is committed.
- Confirm static/dynamic route expectations and auth redirect domains; preview URLs may need allowlisting.

### Rust/Render service unavailable
- Confirm process binds to `0.0.0.0` and `PORT`, Docker image builds, health route returns expected status, required env values validate on startup.
- Inspect sanitized logs for panic/config/dependency/connection errors. Don't return stack traces to clients.
- Add graceful shutdown and request timeouts; check database connection exhaustion.

### Dataset images do not load
- Inspect exact relative path, filename case, extension and asset declaration/build copy.
- Confirm product-to-image mapping and licenses. Use a placeholder for missing mappings rather than a wrong medicine picture.
- Avoid loading the full raw dataset/image collection into the homepage.

### APK download/install failure
- Check release asset exists and the URL actually downloads an APK, not an HTML release page.
- Verify SHA-256, signing identity, application ID/version code and compatibility on a clean Android device.
- Never share keystore/password. Increment version code for a new installable release.

## Incident response
For suspected key/data leakage: restrict/disable affected endpoint, preserve sanitized logs, revoke/rotate compromised secrets in the provider dashboard, invalidate sessions if warranted, review Git history/releases, assess affected records and follow applicable notification duties. Do not publish secrets or personal records in bug reports. After recovery, add a regression test and incident note.
