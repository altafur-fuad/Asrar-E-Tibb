# 14. Testing & Quality Assurance

## 14.1 Baseline commands
Flutter root (after dependencies/toolchain configured):
```powershell
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```
Website (`website/` after implemented):
```powershell
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```
Rust (`backend/` after implemented):
```powershell
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo build --release
```
Run only commands that exist and report exact results. If scripts are absent, add justified scripts or clearly note them. Use a lockfile and reproducible dependency install in CI.

## 14.2 Test layers
- Unit: model parsing, search/filter logic, role decision helpers, status transitions, price arithmetic and validation.
- Integration: Supabase queries/policies, auth lifecycle, Storage policy, Rust endpoints, webhook signature/idempotency.
- UI/widget: loading/empty/error states, form validation, navigation, permissions, responsive layout.
- E2E: signup/sign-in/reset/logout; search medicine; read/post/comment; create reminder; browse/cart/order; download APK; paid consultation in provider sandbox only.
- Security: cross-user negative tests, role escalation, object-ID tampering, unsafe HTML/URL, rate limits, upload validation, secret scan.
- Deployment smoke: Vercel build/routes/redirects, Render health/readiness/logs, Supabase policies, exact APK URL/checksum.

## 14.3 Identity/tenant fixture matrix
Create at least: anonymous user, User A, User B, unverified doctor, verified doctor, verified pharmacist, seller A, seller B, moderator/admin and super-admin. Use synthetic test data only. Tests must prove both allowed and denied cases, not just successful paths.

## 14.4 Core acceptance tests
- Medicine catalog only shows fields actually in the dataset; broken image fallback works; pagination works; Unicode/search inputs are robust.
- User A cannot access User B private records through list, direct ID, filter, API, storage path, cached web state or realtime subscription.
- Users cannot edit trusted role/status/payment/order ownership or totals from UI/network requests.
- Admin moderation and user blocking work under intended permissions and are audited; admin does not see personal notes/reminders by default.
- Comment/like concurrency does not create duplicated likes or inconsistent counts.
- Checkout recalculates totals and validates stock server-side.
- Invalid/replayed payment webhooks do not unlock consultation or change status twice.
- No service-role/secret key is found in client bundle, static files, Git history scan or logs.
- Keyboard focus, labels, contrast, mobile overflow, large text and image alt text are verified.

## 14.5 Release gate
Do not deploy production if critical/high security findings remain without accepted mitigation; migration lacks backup/recovery; build is failing; auth redirects are wrong; user data leakage tests fail; webhook is not verified; or APK URL is not verified. Record unresolved issues, owner acceptance and rollback.
